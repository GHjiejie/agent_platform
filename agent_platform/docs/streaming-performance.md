# Playground 流式输出优化

日期：2026-10-26。验证对象是 `http://127.0.0.1:8010` 的本机 managed 实例，默认模型为 Wylon DeepSeek V4.1 Flash。

## 问题与原因

API 与 Worker 在本机由 supervisor 分别启动。原来虽然启动了 Redis 容器，但没有给宿主机进程配置可连接的 `PLATFORM_REDIS_URL`。Worker 约每 100–130 毫秒写入一次持久文字片段，API 无法收到另一个进程的内存通知，只能依赖 2 秒一次的数据库补偿轮询，造成文字成批跳出。

浏览器原来还会逐个事件更新 React 状态，重建整段历史消息并同步读取滚动高度；结束事件到最终会话快照返回之间，也可能短暂移除正在显示的回复。

## 改动

- managed Redis 只向 `127.0.0.1` 发布端口，默认由 Docker 分配空闲端口。本机网关启动后读取实际映射，将 Redis URL 传给 API、Worker 等运行进程。显式配置的外部 Redis URL 保留。
- 持久事件、游标和服务端鉴权继续作为事实来源。Redis 只唤醒读取；通知丢失或断开时仍由原有数据库轮询修复，不改变事件和账务的持久性。
- 前端立即校验和归并每个 AG-UI 事件，在浏览器动画帧中合并界面更新。终结、错误和断流时立即提交尚未绘制的文字，后台标签页暂停动画帧也不会丢失末尾内容。
- 历史消息内容不变时复用原状态和列表；自动滚动每帧合并一次，且在执行时再次检查用户是否仍跟随底部。用户向上阅读时保持位置。
- 最后收到的回复保留到持久会话快照加载完成，再替换成历史消息；切换对话、组织或卸载后取消旧动画帧和旧请求回写。

这里的动画帧仅用于合并更新，没有添加逐字播放或人为等待。

## 实测

优化前后分别新建测试会话，使用相同默认模型和相同的约 500 字中文随笔提示。客户端按 SSE 收到 `TEXT_MESSAGE_CONTENT` 时记录时间，并通过事件游标关联数据库中对应 `message.delta` 的写入时间。

下表衡量的是**持久片段写入到 SSE 客户端收到的延迟**，不包含模型首字等待时间，也不代表供应商生成速度或浏览器绘制耗时。

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 文字片段样本数 | 85 | 117 |
| 推送延迟中位数 | 1058.3 ms | 15.9 ms |
| 推送延迟 P95 | 1955.18 ms | 26.16 ms |
| 最大推送延迟 | 1975.76 ms | 31.16 ms |
| 有文字到达的 100 ms 时间窗口数 | 7 | 115 |

两次模型生成的实际长度不同，因此比较每个已写入片段的推送延迟，不比较生成总时长。以上为本机两次真实运行的观察值，未作为生产容量或所有网络条件下的延迟保证。

详细采样保存在本机 Git 忽略目录 [优化前](../.data/streaming/before.json)、[优化后](../.data/streaming/after.json)。其中的会话和运行 ID 可在本机运行记录中核对。

## 验证

- 本地网关、生命周期和事件通知相关 Python 测试：40 项通过；另外在一次性独立 Redis 容器中执行原先需要 Redis 的 2 项通知/重连测试，两项通过。合计 42 项。
- AG-UI 解析与 UI 回归：17 项通过，覆盖 240 个突发 Unicode 片段、动画帧暂停、最终快照迟到、切换对话、取消、断流重放、重复事件、组织切换、长对话滚动、移动端和减少动效模式。
- 一次性无上游调用的真实前后端浏览器测试：工具调用、刷新恢复、取消与费用凭据通过。
- 在当前真实 Wylon 模型上另做一次浏览器发送验证，观察到 43 次文字更新；首段文字出现后直到完成均未闪空，浏览器未报告脚本错误。本次采样没有超过 50 ms 的主线程长任务，该观察不代表所有设备或长对话的帧率保证。证据位于 `.data/streaming/real-browser.json` 和 `.data/streaming/real-browser.png`。
- 前端 TypeScript 检查及生产构建通过；改动涉及的 Python 文件 Ruff 检查和格式检查通过。
- 当前本机服务健康检查确认使用 `redis+database`，就绪接口返回 HTTP 200。
