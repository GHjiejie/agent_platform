## 已完成的业务闭环

管理员从零配置模型、输入/输出价格和用户额度，发布 Agent；用户运行多轮会话，Worker 经 LiteLLM 调用模型与白名单工具，SSE 展示增量内容。每次模型调用先检查身份、模型状态、限流、层级累计预算和钱包，再预占额度，收到网关用量后结算。管理员可查看调用与账本，对异常冻结进行人工核实或核销。

所有真实服务路径不使用模拟答案。测试 Gateway 必须由测试显式注入；容器中的模拟供应商由验收脚本在独立项目中启动，正常 Compose 不包含它。

## 实际责任边界

| 架构主题 | 第一版落地 |
| --- | --- |
| 组织与权限 | 持久租户边界，admin/member 两种角色；引导创建一个租户，暂无租户/项目管理界面、跨租户平台管理员、五级角色和 RLS |
| 用户密钥 | 统一服务器端受限 LiteLLM key；浏览器不持有网关密钥；尚未逐用户生成 Virtual Key 或动态同步网关管理配置 |
| Agent 引擎 | LangGraph v3 图循环，calculator/current_time 受控工具；不执行任意代码，不包含外部 MCP |
| 持久执行 | Run、消息、事件、租约/fencing 持久化；浏览器断线恢复；Worker 失联明确失败并保留未确认费用，不包含跨进程图 Checkpoint 续跑 |
| 价格 | 单一 USD 币种、输入/输出总 Token 两档价格；每个 Run 冻结版本。价格必须大于零；不提供免费模型绕过成本控制 |
| 缓存/推理 | 以网关 prompt/completion 总量收费；不重复添加缓存或 reasoning 子项；细分优惠价格留待后续 |
| 供应商费用 | 有独立字段但正常网关通路尚未取得可信供应商成本，显示未知；不复制客户费用冒充供应商成本 |
| 用量证据 | `usage_source=litellm_gateway`；confirmed 表示平台账务已结算，不表示供应商账单确认。LiteLLM 可能补算供应商缺失 usage |
| 报表 | 读取调用与财务事实，费用不依赖陈旧 Worker 投影；累计总览、按上海时区的最近30日趋势、用户/模型明细；暂无物化分析表 |
| 费用账本 | 精确小数、平衡分录、人工入账、幂等结算和人工对账；不含在线支付、真实发票、后付费、账期账单和自动退款流程 |
| 限流 | 租户/用户/模型的滑动60秒RPM/TPM/并发，累计费用上限；多个维度共同满足；0表示禁止、null表示该维度不设上限 |
| 异常差额 | 实际计算费用超预占时最多扣预占额，记录平台承担差额并暂停钱包；人工审阅后可解封，不能悄悄透支 |
| 网关异常 | 调用可能已发送但计量不完整时保留预占；显式人工补证或核销。尚未实现自动扫描 LiteLLM logs/供应商账单补证 |
| 网关管理 | 原生 LiteLLM 管理台、平台管理员入口、managed 一键启动和受限 key 引导/复用；两个控制台独立登录，没有 Outbox 配置同步器，修改平台目录不会修改 LiteLLM provider 配置 |
| 部署与监控 | PostgreSQL/Redis/独立服务、迁移、结构化的安全错误与健康接口；没有完整遥测平台、自动备份和灾备演练 |

## 已执行的验证

最终结果：**86 项 Python 测试通过、2 项独立 Chromium 浏览器端到端测试通过**，React 生产构建和独立容器全链路验收通过。

- Python 测试覆盖身份与 CSRF、账号停用与撤权、跨租户和同租户成员隔离、不可变发布/价格快照、Run 幂等和会话串行。
- 计费测试覆盖并发钱包争用、平衡分录、精确金额、重复结算、累计预算、零配额、未知费用、人工确认/核销和审计失败回滚。
- 4 项测试启动隔离的真实 Redis，执行 Lua 并发准入、跨维度原子拒绝和跨窗口调整；没有用 Python 模拟 Lua。
- Runtime 测试运行实际 LangGraph v3 与 OpenAI SDK SSE 解析，覆盖工具分片、截断 JSON、缺失用量、取消、步数限制和无隐式重试。
- Worker 测试覆盖完整调用/账务、两轮工具、多轮会话、取消/超时、晚到用量、租约丢失、禁止重放、限制与价格变更、失联后投影重建。
- PostgreSQL 和 SQLite 迁移均验证初次升级、结构差异检查、测试库降级和再次升级。
- 真实容器链路运行独立 API 与 Worker，经 PostgreSQL、Redis、LiteLLM 和本地供应商完成登录到模型调用和账务的全流程。API/Worker 无 master key，嵌入 Worker 已关闭。

容器验收中的精确账务样例：入账 10 USD；两次调用各输入 12、输出 4 Token；费率为输入 1 USD/百万、输出 2 USD/百万；两次消费合计 0.000040 USD，余额 9.999960 USD，预占为零，账本一笔入账加两笔消费。统计来自运行链路，未手工插入。

Ruff 检查和格式检查、React TypeScript/生产构建均已执行。浏览器验收覆盖桌面管理闭环、成员权限与停用会话、390px移动端和无横向溢出；使用隔离的无头Chromium，不触碰用户已有浏览器标签页。测试使用独立本地数据库，未连接真实付费供应商。

## 运行参数与故障语义

- 每个 Worker 进程最多并行执行4个 Run；租户最多有32个 queued/running/cancelling Run。调度优先活动运行较少的租户，再按排队时间领取。
- `PLATFORM_RUN_TIMEOUT` 同时限制排队与执行，默认300秒；`PLATFORM_MODEL_TIMEOUT` 默认90秒；`PLATFORM_MAX_RUN_COST` 默认1 USD。
- 模型准入使用完整消息和工具定义的 UTF-8 字节数加协议余量作保守输入预估。这是面向已验证文本模型的估算，不是所有供应商 tokenizer 的数学证明。正式使用新模型前需验证上下文与最大输出语义。
- 预占与身份修改使用同一租户数据库事务锁；Redis 故障拒绝新模型准入，数据库故障不能继续无账本调用。
- 平台一次准入只允许一次上游尝试，SDK和Proxy均禁重试与fallback；如需增加重试，必须先扩展尝试与预占契约。
- 失败或取消不代表零费用；最终计量已收到时即使运行失去执行权仍结算，计量缺失时保留冻结；账务收尾不依赖用户仍拥有执行权限。
- 手工确认和核销要求管理员、原因与内容绑定幂等键。核销会记录平台承担不确定性，不制造虚假的退款交易。
- 当前列表接口最多返回200条，前端CSV导出的是当前加载的明细；完整大数据分页、后台导出和分析存储留待下一阶段。

## 后续演进顺序

先验证实际部署使用的供应商和模型，再逐步增加项目层级/细分角色、网关配置同步、自动账单对账、周期预算和正式账单。待这些业务语义明确后，再扩展知识库、多 Agent、代码沙箱和在线支付；不要以未验收的扩展能力阻塞当前已实现闭环的本地使用。
