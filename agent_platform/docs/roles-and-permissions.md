# 账号与前端角色权限

核对日期：2026-10-16。本文依据当前代码中的前端导航、按钮条件和后端鉴权整理；账号现状另外核对了本机 `http://127.0.0.1:8010` 实例与其 SQLite 数据库。

## 账号、密码与角色的关系

账号以邮箱和密码登录。`owner` 等 7 种角色是授予账号的权限身份，没有每种角色共用的默认账号或密码。

2026-10-28 更新：登录入口已支持新邮箱自动注册并登录，首次设置密码至少 12 位；已有账号继续使用原密码。自助注册只创建全局账号，加入组织仍需接受邀请，不自动授予组织角色或平台角色。下文的本机账号现状为原核对日期的快照。

- 组织角色保存在 Membership 中，同一账号在不同组织可有不同角色。
- 平台角色单独保存，同一账号可以同时拥有多个平台角色，也可以拥有组织角色。
- 当前本机实例只有 `admin@example.com` 一个账号，在“我的组织”中为 `owner`，没有任何平台角色。其余 6 种角色没有对应账号。
- 账号的初始密码来自 `agent_platform/.env` 的 `PLATFORM_ADMIN_PASSWORD`。本次已验证它与当前数据库密码哈希一致，并实际登录成功。已有账号的密码不会因为修改该环境变量而自动改变。
- 明文凭据与按角色汇总的账号现状保存在本机文件 [role-accounts.local.md](../.data/role-accounts.local.md)。该文件位于 Git 忽略的 `.data/`，权限为 `0600`，仅当前系统用户可读写。本说明不复制密码。
- 数据库只保存密码哈希。后续如果账号密码已修改且没有另行保存明文，无法从角色或哈希中读出原密码。

这份账号现状只描述本次检查的本机实例，不代表其他部署或测试数据库。历史 `platform_users.role = admin` 是兼容字段，不表示拥有 `platform_admin` 权限。

## 菜单判定规则

以下矩阵以账号正常、组织正常运行、组织成员关系有效为前提。组织矩阵假设账号没有额外的平台角色；平台矩阵只描述平台角色增加的菜单，不假设账号同时加入某个组织。

前端根据 capability 判断菜单。一个账号的实际菜单是当前组织角色与平台角色的可见菜单合并；切换组织后，组织内权限随成员关系变化。

所有已登录账号都能看到“接受组织邀请”，并通过右上角账号设置修改密码、退出登录；有有效成员关系的账号可以切换组织。这些公共入口未在下表重复列出。

补充说明：

- 运行记录和会话正文始终按本人隔离。`owner`、`tenant_admin`、`finance_viewer` 可以查看组织调用元数据，不因此获得其他成员的会话正文。
- “运行元数据”导出固定为本人范围；组织范围只开放调用元数据与费用，不包含会话正文。`finance_viewer` 的导出表单也提供本人运行元数据选项，但它没有运行任务或打开运行记录页面的权限。
- 成员管理不提供直接设置 `owner` 的角色选项；所有权通过专门的转移操作变更。移除组织成员不等于全局停用账号。
- 组织内“模型目录”始终以 `admin={false}` 渲染，组织管理员只能维护模型选择策略，不能在那里新增模型部署或修改报价。
- 支持访问默认 15 分钟，可填写 1–60 分钟；默认仅运行元数据。读取会话正文需要所有者单独勾选批准。

## 能力清单与当前界面的差异

1. **组织关闭**：`owner` 的 capability 集合中存在 `tenant.close`，但当前路由只有 `/api/v2/platform/tenants/{tenant_id}/close`，服务实际检查 `platform.tenants.manage`。因此仅有 owner 身份不能在现有界面或该接口关闭组织。
2. **平台审计**：平台管理、平台财务角色都拥有 `platform.audit.read`，后端提供 `/api/v2/platform/audit`；当前前端没有独立的平台审计菜单或面板。组织内“审计日志”仍要求 `audit.read`。
3. **供应商成本**：平台财务拥有 `platform.costs.read`，后端提供 `/api/v2/platform/costs` 等成本能力；当前前端没有供应商成本总览或成本预算配置入口。当前财务操作面板主要是组织钱包、入账、预占和人工处理。
4. **历史说明**：`apps/web/README.md` 中仍有第一版 admin/member 与账本权限描述；当前实际导航和操作权限以本文引用的 v2 实现为准。普通 `member` 没有“费用中心”菜单，`finance_viewer` 则有。

## 组织暂停或关闭中的行为

组织状态不是 `active` 时，前端只保留角色有权访问的“调用统计”“费用中心”“模型目录”“审计日志”“支持访问授权”。概览、Agent、Playground、运行记录、成员管理和配额页面隐藏。

此时模型策略修改入口关闭；支持访问面板不再提供新增授权按钮。后台导出仍会按当前权限和组织生命周期复核；进入清理/删除阶段后拒绝导出。平台级菜单继续按平台角色展示，已有费用可由平台财务处理。

## 开通其他角色账号的现有流程

1. 用户可直接在登录页用新邮箱和至少 12 位密码自动注册并登录；也可以由平台管理员在“平台运营 → 开通成员账号”预先创建。账号密码由用户或创建者指定，不由角色推导。
2. 组织所有者在“成员管理”邀请对应邮箱，并选择 `tenant_admin`、`member` 或 `finance_viewer`。受邀者用相同邮箱登录并接受邀请；组织管理员只能邀请普通成员或财务查看员。
3. 平台管理员在“平台运营 → 平台角色”按完整邮箱查询账号，再授予所需平台角色。平台角色与加入组织分别操作。
4. 新组织的 owner 在“平台运营 → 开通组织”指定；已有组织通过“成员管理 → 转移所有权”交接。

当前本机唯一账号没有平台角色，因此看不到上述平台账号开通入口。首次平台操作员需通过显式初始化配置 `PLATFORM_OPERATOR_EMAILS` 引导；该过程会授予指定已有账号 `platform_admin` 和 `platform_finance`，属于另一次权限变更。本次只核对与记录，没有创建账号、重置密码或授予角色。
